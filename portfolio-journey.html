Architecture: three independently testable layers. Extractor — extract_product() wraps all field access in try/except and returns None on any error; extract_data() skips None results with continue, so a single broken card never crashes the run. Transformer — validation chain ordered to fail fast: null titles → null prices → digit check (rejects "Price Unavailable") → type normalization. Currency conversion uses an environment variable with a safe default, not a hardcoded constant — changing the rate requires no code change. Loader — save_csv(), save_postgres(), save_gsheet() each follow the same interface contract: check empty → write → catch exceptions. One failing destination never blocks the others.

DecisionImplementationWhy
Per-card failure isolation try/except inside extract_product() returns None; outer loop skips with continue A broken card costs one row, not one run. Scraping 50 pages × ~30 products means any single malformed card must not abort 1,500 other records.
Null-first validation order in Transformer Check null title → null price → digit validation (rejects "Price Unavailable") → type coercion Fail-fast on the cheapest check prevents expensive downstream type errors. Validating digit format before type conversion avoids silent NaN propagation into PostgreSQL.
Currency via environment variable os.getenv("CURRENCY_RATE", default=1.0) in Transformer Hardcoded constants require a code change and redeploy for every rate update. An env var makes it an operations concern, not a development concern.
MagicMock at every I/O boundary DB connections, HTTP requests, and file handles all patched; integration tests use isolated test schema Mocking at the boundary forced injectable dependencies. The architecture improved because tests demanded clean interfaces — 0 live deps in CI means no flaky tests.
ChallengeSolutionKey Learning
Single broken product card (null price, malformed HTML) crashed the entire scrape loop Per-card try/except in extract_product() returning None; main loop skips None with continue. A broken card costs one row, not the whole run. Fail-safe per unit, not per run. Graceful degradation means the pipeline keeps going rather than stopping and leaving operators with no data.
Testing required live DB connections and real HTTP calls — slow CI, flaky tests MagicMock patches DB and HTTP at the boundary; integration tests use a dedicated test schema cleaned between runs. 0 live dependencies in the unit test suite. Mocking boundaries forces clean interfaces — the architecture improved because the tests demanded injectable dependencies at every I/O boundary.
Key Takeaway

When the source HTML structure changed mid-project, only the Extractor needed updating — Transformer and Loader were unaffected. Separation of concerns is maintenance cost, measured in lines changed during the next schema break.

Fail Isolation Pattern
The per-card try/except pattern is idiomatic production ETL: isolate failure to the smallest meaningful unit. One broken product costs one row, not one run. Defining failure domains before success paths is the correct order of thinking.
Tests as Architecture Driver
MagicMock at every I/O boundary didn't just enable testing — it forced injectable dependencies. The architecture improved because the test suite demanded clean interfaces. 100% branch coverage is a design constraint, not just a quality metric.
Thread Forward
The failure-isolation mental model from this ETL pipeline reappears in Banking Router's tier isolation: if Tier 2 (RAG) fails, the system falls back to Tier 3 (LLM) rather than crashing. Same pattern — define what failure looks like before you define success.

What I discovered in EDA changed the modeling approach entirely: HS and Abusive labels correlate at r=0.96, meaning they almost always co-occur. High correlation isn't a complexity signal — it's a simplification signal. That insight drove the label strategy and cut the classification problem in half.
Goal Classify Indonesian tweets into hate speech, abusive language, and combinations; surface EDA insights on label co-occurrence; deploy real-time inference via Flask REST API. Dataset 13,169 rows · 11,969 train · 1,075 test · Labels: HS · Abusive · HS+Abusive · Weak HS · Clean · 55.7% negative content Stack Python · Pandas · scikit-learn · TF-IDF · LinearSVC · Flask · joblib pipeline serialization

Key EDA finding: 55.7% of tweets carry negative content. Pearson correlation between HS and Abusive labels: r = 0.96 — hate speech almost always co-occurs with abusive language, sharing a latent signal a single classifier can exploit. This reduced the multi-label problem to a simpler compound-class boundary without losing discriminative power. The Flask API serializes the full preprocessing pipeline via joblib — tokenization, TF-IDF vectorizer, and classifier — so identical transforms apply at training and inference with no divergence risk.

DecisionApproachWhy
Label strategy: compound class Collapsed HS+Abusive into one compound label instead of two independent heads r=0.96 co-occurrence means separate heads are redundant — they'd learn the same signal twice. Compound class is simpler and doesn't lose discriminative power.
Vectorizer: TF-IDF Unigram + bigram TF-IDF with Bahasa preprocessing (stopword removal, normalization) Indonesian informal Twitter text has high surface variation (slang, abbreviations). TF-IDF on n-grams captures partial forms ("gbl" for "goblog") without requiring full stemming.
Classifier: LinearSVC LinearSVC with class_weight='balanced' for imbalanced HS class LinearSVC performs well on high-dimensional sparse vectors from TF-IDF. class_weight='balanced' compensates for the minority HS class without SMOTE (preserves text distribution).
Deployment: joblib pipeline Full scikit-learn Pipeline (preprocessor + vectorizer + classifier) serialized and loaded at inference Serializing the full pipeline — not just the model — guarantees identical preprocessing at inference. Prevents train/serve skew from different tokenization at call time.
ChallengeSolutionKey Learning
Multi-label setup with r=0.96 inter-label correlation created redundant classification heads Collapsed correlated label pairs into compound class; simplified head without losing signal High label correlation is a simplification signal, not a complexity signal. When two labels are 96% correlated, they share a latent feature — one classifier covers both.
Indonesian slang ("gw", "lo", "bgt", "yg") not in standard vocab — standard tokenizers missed ~30% of signal-bearing tokens Custom slang normalization dictionary before vectorization; bigram features capture partial forms not normalized Indonesian informal text requires language-specific preprocessing. AquaSense — Plankton Density Sensor Reliability & YOLOv8 IAA Analysis
Bland-Altman agreement analysis · ICC(A,1)=0.889 · M2 vs M3 CCC=0.984 · zero-inflation diagnosis
2024
Solo project
Data Analyst
↗ HuggingFace Model ⌥ HuggingFace Dataset
Why this project: The stakeholder asked for Pearson r as the reliability metric. I built this project to demonstrate why that's the wrong question — and to deliver the right answer instead. Two counting methods can correlate at r=0.99 while differing by 30,000 cells/mL on every individual measurement. Pearson tells you about the relationship; Bland-Altman tells you about the disagreement. Only one of those answers the operational question.
Goal Assess whether three plankton counting methods are interchangeable — using Bland-Altman limits of agreement, ICC, and CCC rather than Pearson correlation alone. Data context 3 counting methods (M1 manual microscopy · M2 automated cell counter · M3 image processing) · Green Algae · heavy zero-inflation in M1 rows Stack R · Python · Bland-Altman analysis (mean vs. difference, ±1.96 SD LoA) · ICC(A,1) via pingouin · CCC · Tidy data restructuring from wide-format sensor logs

Three pairwise Bland-Altman comparisons revealed a critical finding: M1 vs M2 and M1 vs M3 both showed large negative bias (~−49,000 cells/mL) with proportional error — the disagreement grows as concentration increases, a pattern that cannot be corrected by a scalar offset. By contrast, M2 vs M3: near-zero bias (+694 cells/mL), CCC=0.984 — effectively interchangeable. Recommendation: use M2 or M3 as the reference for model training; exclude or recalibrate M1 Green Algae counts before any downstream use.

Bland-Altman Analysis Panel — Inter-Annotator Agreement (CS2)
Three pairwise Bland-Altman plots. M1 vs M2 dan M1 vs M3: large negative bias (~−49k cells/mL), wide limits of agreement — proportional bias yang tidak dapat dikoreksi dengan scalar offset. M2 vs M3: near-zero bias (+694), CCC=0.984. Spearman=0.630 misleadingly low due to zero-inflation.

Spearman for M2 vs M3 returned 0.630 — misleadingly low. Root cause: zero-inflation. Many rows have M1 reporting exactly 0, creating large tie-groups that collapse Spearman's rank signal. CCC=0.984 was the correct metric for this data structure — not Pearson (assumes normality), not Spearman (sensitive to tied ranks from zeros), not ICC alone (ignores systematic bias).

Statistical ChoiceMethod UsedWhy Not the Obvious Alternative
Method agreement metric Bland-Altman LoA (mean vs. difference plot) Pearson r=0.99 can coexist with a systematic 49k cells/mL bias. Bland-Altman is the only metric that directly answers "how much do these methods disagree on any given sample?"
Reliability coefficient CCC (concordance correlation coefficient) Spearman=0.630 was misleading due to zero-inflation (many tied zeros collapse Spearman's rank signal). CCC=0.984 for M2 vs M3 correctly captures both precision and accuracy jointly.
Distributional reporting Skewness + kurtosis alongside mean/median Mean alone hides the heavy right tail from outlier samples. Skewness evidence justifies the non-parametric method choice before reviewers question it.
ChallengeSolutionKey Learning
Stakeholder requested Pearson r as reliability metric — but r=0.99 can coexist with a systematic 30% bias Demonstrated the limitation empirically; replaced Pearson with Bland-Altman ±1.96 SD limits of agreement as the primary metric Correlation = linear relationship. Bland-Altman = agreement. For method comparison studies, only agreement analysis answers the operational question.
M2 vs M3 Spearman=0.630 seemed to indicate low agreement — but CCC=0.984 Diagnosed zero-inflation as root cause: many rows had M1 reporting exactly 0, creating large tie-groups that collapse Spearman's rank sensitivity Always diagnose why a metric gives an unexpected result before reporting it. Zero-inflation is a structural data issue — not a methods disagreement issue.
Key Takeaway

Choosing the right statistical test is an architectural decision. A method with r=0.99 and a +20% systematic bias will still fail operationally. The test must match the question being asked — "are these methods interchangeable?" requires agreement analysis, not correlation.

Metric Matches the Question
The stakeholder's question was "can we replace M1 with M2?" — an agreement question, not a correlation question. Pearson r can be 0.99 while the methods differ by 49k cells/mL on every measurement. Framing the analysis correctly is the analyst's first deliverable.
Zero-Inflation Diagnosis
Spearman=0.630 vs CCC=0.984 for M2 vs M3. Root cause: zero-inflation collapsed Spearman's rank signal. When two metrics disagree, diagnose the data structure before choosing which to report. The diagnosis (zero-inflation) is the finding, not the number.

Telegram Bot — Production Deployment
Deployed sebagai Telegram bot accessible ke seluruh mahasiswa informatika 24/7. Menjawab FAQ tentang administrasi akademik tanpa keterlibatan staf.

The system builds a TF-IDF term-document matrix from all FAQ entries, applies SVD decomposition to reduce to k=50 latent semantic dimensions, then classifies new queries via KNN with cosine similarity in that reduced space. Key preprocessing: Nazief-Andriani stemmer for Indonesian morphology — English stemmers fail on Bahasa affixation patterns ("mempertimbangkan" → "timbang"). The trained SVD matrix and KNN index are serialized and loaded at PHP inference time via JAMA libraries — no Python needed at serve time.

DecisionConfigurationWhy
Stemmer: Nazief-Andriani Indonesian morphology via Sastrawi/Nazief-Andriani library Indonesian affixation is complex: "mendaftarkan", "pendaftaran", "daftar" must reduce to the same root. Porter Stemmer (English) would corrupt these entirely. No language-agnostic stemmer was available for PHP.
Dimensionality: k=50 SVD TF-IDF matrix → SVD → 50 latent dimensions k=50 balances semantic generalization vs. corpus specificity. At k=5, too much compression loses topic boundaries; at k=200, noise from rare terms re-enters. k=50 was tuned on held-out accuracy.
Distance: Manhattan over Euclidean KNN with Manhattan distance metric Compared both empirically on validation set. Manhattan outperformed Euclidean on LSA-projected sparse vectors in this domain — LSA coordinates are not isotropic, making taxicab distance more appropriate than Euclidean.
Inference: PHP JAMA matrix load Precomputed SVD matrix serialized as JSON; PHP loads + applies transform at query time No Python runtime in PHP production environment. Inference = one matrix multiply (query vector × precomputed projection matrix). Training runtime irrelevant to serving — only serialized parameters matter.
ChallengeSolutionKey Learning
KNN on raw TF-IDF sparse vectors failed on synonym variation — "biaya" vs "bayar" (both "payment") share no surface tokens but mean the same thing LSA projects both terms to nearby positions in the k=50 latent semantic space — geometric proximity reflects semantic proximity regardless of surface word choice SVD creates a continuous meaning space from a discrete co-occurrence matrix. This is the same operation transformers do at scale (learned rather than counted). Understanding SVD from scratch made SBERT immediately intuitive.
PHP production runtime had no Python — couldn't call the training environment for inference Serialized trained SVD matrix + KNN index; PHP loads and applies the matrix transform via JAMA. Inference = one matrix multiply. Inference is just a matrix transform on new input. The training runtime is irrelevant to production serving — only the serialized parameters matter.

Architecture DecisionConfigurationWhy
Embedding layer Vocab 100,000 · dim 128 · trainable Captures Bahasa Indonesia slang: "gue", "gapapa", "tdk", "udh", "bgt" — fixed pretrained embeddings (Word2Vec) trained on English or formal Indonesian miss these completely. Domain-specific vocab required trainable embeddings.
Regularization SpatialDropout1D(0.4) + L2(0.001) + recurrent_dropout=0.4 Tweets are 5–30 tokens — high overfitting risk without explicit regularization on short, noisy inputs. SpatialDropout1D drops entire embedding dimensions (vs. individual values), which is more effective for sequence data.
Bidirectional LSTM BiLSTM 64 units — processes sequence forward and backward Bidirectional context detects irony and implicit negative sentiment. "Bagus banget ya" (sarcasm) requires both directions — left-to-right misses the sarcastic modifier at the end; right-to-left alone misses the setup.
Neutral class handling Oversampled before training (10% of dataset) Without oversampling, neutral recall collapsed below 30%. Neutral class is only 10% of the dataset (positive 58%, negative 31%). The model defaulted to positive/negative predictions and ignored neutral entirely.
Data leakage fix KFold strictly on training set only — test set never used in fold generation Found a bug from 2023 submission: KFold was applied across the full dataset including the test set. Corrected — honest accuracy is 91.09%, not the inflated 92%. Reported the lower number.
Key Takeaway

For well-defined classification tasks with domain-specific training data, a fine-tuned model outperforms zero-shot GenAI on all three production dimensions simultaneously: accuracy (+7.7pp), speed (3,200×), cost ($0 vs $62/yr). GenAI's advantage is generalization to new task types. Classical ML wins on known tasks with labeled data. This directly shaped the Banking Intent Router: use an LLM only where a classifier genuinely can't cover the query.

GenAI Insight — Zero-Shot Best
Zero-shot (85.3%) outperformed 3-shot, 5-shot, 10-shot, and Chain-of-Thought. Few-shot examples from e-commerce domain actively hurt accuracy — wrong-domain examples are noise, not signal. Domain adaptation matters more than example count when prompting LLMs.

HealthTruth-AI v0 — Hackathon Submission
Tampilan awal v0: linear RAG chain dengan FAISS in-memory. Hardcoded cosine threshold gate — jika top-1 cosine similarity <0.6, mengembalikan fallback message. Gate binary (block/pass) tanpa kemampuan routing berdasarkan confidence level.

Added a similarity threshold gate: if top-1 cosine similarity <0.6, return a fallback message instead of generating — preventing the worst hallucinations. But the gate was binary (block/pass) with no ability to route differently based on confidence level.

ChallengeSolutionKey Learning
Linear chain generated confidently even when FAISS returned low-relevance documents — cited real documents for wrong answers Hardcoded cosine similarity threshold (<0.6 → return fallback instead of generating) A RAG pipeline without a retrieval quality gate is a hallucination machine with citations. But a hardcoded threshold can't distinguish "zero docs" from "tangential docs" — it just blocks both equally.
What This Unlocked → Level 5B

The binary gate didn't allow graded responses: both "no docs found" and "low-confidence docs found" returned the same unhelpful fallback. The fix required conditional flow — a graph, not a chain. This gap motivated the full v1 rewrite with LangGraph.

RAG Without Routing = Risk
A linear chain generates confidently even when retrieval returns low-relevance documents — cited real documents for wrong answers. A similarity gate is necessary but a binary block/pass has no ability to route differently based on confidence level. Conditional flow was the missing piece.
Chunking Trade-off Measured
300 tokens: better retrieval precision@3 but truncated answers. 1,000 tokens: complete answers but noisy retrieval (too much irrelevant context in the chunk). 500 tokens empirically balanced precision and completeness — measured, not assumed.
Thread Forward to v1
The binary gate's inability to distinguish "no docs" from "tangential docs" precisely defined the v1 requirements: conditional routing per confidence regime, not binary block/pass. The limitation of v0 was the specification for v1.
